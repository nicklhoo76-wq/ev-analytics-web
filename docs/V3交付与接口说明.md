## 订单汇总接口（待Flask实现）

`GET /api/v1/analytics/orders`

| 参数 | 含义 |
|---|---|
| dataset_id、batch_id | 与现有接口一致的数据集及批次 |
| as_of | 北京时间观察时点，包含时区 |
| window_hours | 24或168，分别为近24小时和近7天 |
| station_id | 可选；省略代表展示范围内的全部站点 |

响应示例（字段名可用snake_case；枚举值与字典键保持原样）：

```json
{
  "data": {
    "as_of": "2023-04-09T20:00:00+08:00",
    "window_hours": 24,
    "total": 10,
    "statuses": {"created": 1, "billed": 2, "paid": 6, "refund_approved": 1},
    "types": {"BJS-TOU-VALLEY": 4, "BJS-TOU-FLAT": 3, "BJS-TOU-PEAK": 3}
  }
}
```

统计口径：订单创建时间落在`[as_of-window_hours, as_of)`；每笔订单取`event_time <= as_of`的最后状态事件。不可直接读取最终订单状态，否则会把观察时点之后的支付或退款提前算入。状态与类型分别互斥计数，两者各自的合计均等于total；缺失类型可使用unknown，并呈现未知类别。事件时间相同时，后端须用确定的事件序号排定先后。

状态码：created未计费、billed待支付、paid已支付、refund_requested退款审核、refund_approved已退款、waiver_requested免单审核、waiver_approved已免单。这里的“类型”定义为订单电价时段类型，不是预约/即时充电类型；现有数据没有后者的分类依据。

无订单应返回total为0的有效统计；统计暂不可用可返回`data:null`或明确错误，前端显示“该窗口订单统计暂不可用”，不冒充0单。

当前Mock订单汇总来自成员1development生成结果的fact_order与fact_order_event，由`scripts/prepare-orders.cjs`预处理，输出`src/data/order-summaries.json`。只提取前端已有三个观察时点及两个窗口；Mock按展示8站过滤汇总。前端包不包含原始用户或订单标识。此脚本仅处理小规模development单分片，不是GB级生产ETL；正式汇总由成员2使用SparkSQL完成。

## 预警口径

- 阈值 = 站点装机容量kW × 设置百分比，默认80%，允许10%—100%。阈值按浏览器本地保存。
- 小时平均预测负荷严格大于阈值才触发。相邻且连续的超限小时合并；负荷缺失、低于/等于阈值或时间断档均中断合并。
- 预警列表按峰值占装机容量比例降序排列，可点击站点联动。区间显示北京时间起止时间，同时标注峰值和阈值。
- 全网曲线的参考线按全网站点装机容量合计计算；列表逐站计算，因此全网未超线时仍可能有单站提醒。
- 只使用站点级预测，不推断“某号桩负荷过高”。装机容量缺失或非正数不计算该站阈值；预测缺失不视作安全。
- 当前为前端根据预测结果计算的展示提醒，未新增后端告警记录、短信、工单或处理状态。预测覆盖数表示所选时域内至少有一个有效负荷预测的站点数，不保证每站小时数据齐全。

## 空闲预测和热力图

充电窗口使用每个小时末的predictedFreePiles；柱高、悬浮数值、固定时点和推荐时点使用同一字段。当前与未来对比取所选1/6/24h的最后一个预测点。正式接口需按时间升序给出连续的小时区间；缺失点以null占位，不能直接删行或用0填补。空闲数应为0至站点充电位总数范围内的整数。

热力图使用站点×小时历史平均负荷。悬停仅强调所在格，提示站点名称、编号、北京时间和kW数值。没有历史值的格子不绘成0负荷。
